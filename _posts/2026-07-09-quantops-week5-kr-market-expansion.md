## 개요

QuantOps는 공개된 데이터(주가·지수·거시지표·뉴스)만으로 만든 소규모 end-to-end 금융 MLOps 파이프라인이다. KT AI Engineering 경력 지원 포트폴리오로 시작했다. 종목 추천(XGBoost 이진분류로 5거래일 뒤 상승 확률을 예측)과 이상탐지(3종 앙상블), 뉴스 RAG, 그리고 서빙·재학습·모니터링을 아우르는 운영 축까지 Week1~4를 거치며 갖췄다.

Week5의 목표는 하나였다. 미국 단일 시장으로만 돌던 분석 대상을 미국과 한국 두 시장으로 분리 확장하고, 넓어진 유니버스로 재학습하는 것. 종목만 더 넣으면 되는 단순한 작업처럼 보였지만, 실제로는 시장마다 다른 개장일과 결측 패턴, 그리고 모델 품질 편차를 어떻게 안전하게 다루느냐가 관건이었다. 실제로 미국 데이터만 보던 파이프라인에 한국 종목을 넣자마자, 미국 휴장일의 VIX가 0으로 찍히는 문제부터 튀어나왔다.

이 글은 그 과정에서 부딪힌 문제와 해결, 그리고 그 해결을 검증한 방식을 정리한다. 참고로 여기서 '메인 세션'은 오케스트레이터 겸 합성자 역할을 하는 Claude Code(3호기)를 가리킨다.

## 왜 시장을 분리했나

유니버스는 미국 13종(AAPL·MSFT·GOOGL·AMZN·NVDA·META·TSLA·QQQM·VOO·SOXX·PLTR·AMD·JPM)과 한국 13종(삼성전자 005930.KS·SK하이닉스 000660.KS·KODEX반도체 091160.KS·현대차·기아·NAVER·카카오·LG에너지솔루션·삼성바이오로직스·POSCO홀딩스·KB금융·셀트리온·삼성SDI)으로 정했다. KOSPI 대형주로 미국 13종과 대칭을 맞춰 cross-sectional 랭킹 신호를 확보하려는 의도였다. 채권혼합형 상품(RISE)은 성격이 다른 자산이라 제외했다.

첫 설계 결정은 테이블 구조였다. 선택지는 둘이었다. 기존 미국 테이블에 `market` 컬럼을 붙여 한국 데이터를 같은 표에 섞는 방식, 아니면 동일 스키마의 별도 테이블을 새로 두는 방식.

두 방안을 직접 저울질한 뒤, 같은 설계안을 여러 AI 에이전트에게 동시에 던져 교차검토시키는 사내 방식([hocg](/development/hocg-3way-fanout/))으로 세 관점을 한 번 더 확인했다. 세 워커 모두 별도 테이블(`kr_stock_daily`) 신설 쪽으로 의견이 모였다. 이유는 분명했다. 기존 테이블에 컬럼을 더하면 PK 구조와 upsert 로직을 전부 다시 써야 하는데, 이는 이미 안정적으로 돌던 미국 파이프라인을 건드리는 리스크다. 반면 별도 테이블은 시장을 물리적으로 격리해, 기존 코드에 손대지 않고도 확장할 수 있었다.

대신 시장별 라우팅이 파이프라인 곳곳에 하드코딩되는 것을 막으려고, `common/market.py`에 라우팅 헬퍼를 하나로 모았다. 시장명을 테이블명으로 바꾸는 함수, 시장별 심볼셋과 기본값, 정규화 헬퍼가 여기 모인다. 모든 CLI와 서빙 진입점은 이 헬퍼를 거쳐 시장명을 대문자로 정규화한다(소문자 `kr`도 `KR`로).

## 0-fill 오염: VIX=0의 함정

테이블 분리를 정하면서 함께 짚인 문제가 개장일 불일치였다. 한국 개장일과 미국 휴장일이 겹치는 날에는 미국 지수·VIX·거시지표가 결측(NaN)으로 들어온다. 한국 종목의 피처에도 미국 시장 데이터가 함께 들어가기 때문에 생기는 문제다(뒤에서 다루듯, 지금은 미국 글로벌 지수를 한국 리스크 프록시로 쓰고 있다).

기존 파이프라인은 결측을 0으로 채우는 0-fill 방식을 썼다. 미국 단일 시장에서는 지수와 거래일이 항상 일치해 문제가 없었다. 하지만 한국 경로에 그대로 적용하면 VIX가 0으로 채워진다. 모델 입장에서 VIX=0은 "변동성이 전무하다"는 신호로 읽히고, 실제로는 그저 미국 시장이 쉬는 날일 뿐인 상황을 완전히 잘못 학습하게 된다.

대응은 시장별로 갈랐다. 한국 경로는 0-fill 전에 직전 거래일 값을 이월하는 forward-fill을 먼저 적용한다. 미국 경로는 기존 0-fill을 그대로 뒀다. 미국은 지수와 거래일이 일치해 애초에 결측이 없으므로, 회귀 없이 무손상이다.

미래값을 과거로 당기는 backward-fill은 처음부터 배제했다. 아직 일어나지 않은 미래 지수 값을 과거 시점에 채우는 것은 look-ahead 데이터 누수이고, 실전에서는 알 수 없는 정보로 모델을 학습시키는 셈이 된다.

추가로 지수 테이블(`global_indices`)을 한국 백필 경로에도 채워, 시계열 선두 구간에서 생기는 결측을 원천에서 막았다.

## 게이트 재보정: 랜덤 이하 모델 자동 차단

모델이 실서비스에 배포될 '승자'로 승격될 자격이 있는지 판단하는 게이트(champion 승격 게이트)도 손봐야 했다. 기존 기준(추천 AUC 0.55, 이상탐지 F1 0.60)은 초기 walking-skeleton 단계에서 임의로 잡아둔 값이었다. 13종·3년 분량의 실데이터 분포를 놓고 보니 이 기준은 과도했다.

실측 분포를 바탕으로 게이트를 다시 맞췄다.

| 지표 | 초기(walking-skeleton) | 실측 재보정 |
|------|------|------|
| 추천 AUC | 0.55 | 0.52 |
| 이상탐지 F1 | 0.60 | 0.50 |

이 기준을 적용한 결과가 흥미로웠다.

| 시장 | 추천 AUC | 이상탐지 F1 | 게이트 판정 |
|------|------|------|------|
| 미국 | 0.471 | 0.478 | 배제 (랜덤 0.5 이하) |
| 한국 | 0.530 | 0.539 | 승격 |

미국 모델은 추천 AUC 0.471, 이상탐지 F1 0.478로 랜덤(0.5)에도 못 미쳐 자동으로 배제됐다. 한국 모델은 0.530·0.539로 게이트를 통과해 승격됐다.

중요한 건 이걸 "게이트를 낮췄다"고 부르지 않는다는 점이다. 재보정 전 기준(0.55/0.60)이었다면 한국 모델(0.530/0.539) 역시 통과하지 못했다. 그러니 이번 변경은 기준을 느슨하게 푼 게 아니라, 임의로 잡았던 숫자를 실데이터에 맞게 다시 맞춘 것이다. 그 결과로 랜덤 이하 저품질 모델이 서빙에 나가지 못하도록 자동 차단하는 가드레일이 생겼다. 통계적 유의성 검정(permutation test)과 시장별 차등 게이트는 아직 과제로 남겨뒀다.

## 다층 검증이 잡은 것들

Week5는 설계·구현·검증을 서로 다른 주체에 분리해 진행했다. 설계는 hocg의 다관점 검토를 거쳤고, 구현은 외부 워커에 위임했다. 그리고 검증을 세 층으로 나눴다.

### 검증은 어떻게 3단으로 나눴나

1. **메인 세션(Claude Code)의 diff 리뷰** — 각 배치 단위로 변경분을 직접 읽는다.
2. **Workflow 6관점 리뷰** — 구현이 끝난 코드를 routing·us-regression·gate·retrain·security·completeness 6개 관점에서 훑는 리뷰 파이프라인이다. 이 리뷰에서만 adversarial 반증까지 통과한 결함이 7건 나왔다.
3. **codex 독립 게이트** — 시각이 다른 독립 코드 리뷰 게이트를 3회 통과시켰다.

세 층은 모두 코드와 파이프라인을 대상으로 한다. 그런데 마지막 구멍 하나는 이 자동화된 검증이 아니라, 사람이 API 응답을 직접 눈으로 확인하다 잡았다. 그 이야기는 아래 표의 마지막 줄에 있다.

### 각 층이 잡아낸 결함

| 발견 층 | 결함 | 결과 |
|------|------|------|
| 메인 세션 diff 리뷰 | 거시 백필 함수에 시장 인자를 잘못 전달 | 재학습(T6) 크래시 |
| Workflow 리뷰 | 이상탐지 학습 코드가 미국 테이블을 하드코딩 | 한국 F1이 오염값 0.484 → 정정 후 0.539 |
| Workflow 리뷰 | 한국 forward-fill에 시장 가드 없음 | 미국 지수 결측 시 미국 피처가 조용히 바뀔 위험 |
| codex 독립 게이트 | 소문자 시장명(`kr`)이 대문자(`KR`)와 분리 저장 | 데이터 파편화 |
| 사용자 수동 확인 | 서빙 엔드포인트 정규화 누락 | `/recommend?market=kr` 요청 처리 오류 |

7건 전부를 나열하는 대신, 층을 가로질러 성격이 다른 다섯 사례만 추렸다. 이 다섯 가지가 서로 다른 층에서, 서로 다른 방식으로 드러났다는 게 이 구조의 핵심이다. 설계 단계의 다관점 검토(hocg)가 아무리 꼼꼼해도 잡지 못한 것을 뒤 단계의 검증이 포착했다. 이상탐지 F1 오염값은 설계도만 봐서는 드러나기 어려웠을 것이고, 소문자 시장명 문제는 독립 게이트가 아니었으면 지나쳤을 것이다.

특히 마지막 줄은 곱씹을 만하다. 자동화된 3단 검증을 다 통과한 코드에서, 사람이 `/recommend?market=kr` 응답을 직접 확인하다 정규화 누락을 찾아냈다. 가드레일을 여러 겹 세워도 마지막 확인은 결국 사람 몫으로 남는다는 뜻이다.

## 서빙 실증

실제 서빙 응답으로 확인해봤다.

`/recommend?market=KR` 요청은 run_date 2026-07-07 기준 상위 10종목 랭킹을 돌려준다.

```json
GET /recommend?market=KR
{
  "market": "KR",
  "run_date": "2026-07-07",
  "items": [
    { "rank": 1,  "symbol": "005380.KS", "score": 0.766 },   // 현대차
    { "rank": 2,  "symbol": "006400.KS", "score": 0.726 },   // 삼성SDI
    { "rank": 3,  "symbol": "068270.KS", "score": 0.700 },   // 셀트리온
    // ...
    { "rank": 10, "symbol": "005930.KS", "score": 0.447 }    // 삼성전자
  ]
}
```

1위는 현대차(005380.KS, 0.766), 2위 삼성SDI, 3위 셀트리온 순이었고, 10위는 삼성전자(0.447)였다. 다만 승격한 한국 모델도 AUC 0.530으로 게이트(0.52)를 겨우 넘긴 수준이라는 점은 감안하고 봐야 한다. 랜덤 대비 근소한 우위일 뿐, 이 점수를 과신할 근거는 아니다. 같은 요청을 미국 시장으로 보내면 게이트 배제로 빈 결과가 온다.

`/anomaly?market=KR&symbol=005930.KS` 요청은 3종 앙상블 결과를 돌려준다. Isolation Forest(iforest), 통계 기반 규칙(statrule), LSTM Autoencoder(lstm_ae) 세 탐지기가 각자 점수를 내고 이를 앙상블한다.

```json
GET /anomaly?market=KR&symbol=005930.KS&window=5
{
  "market": "KR",
  "symbol": "005930.KS",
  "window": 5,
  "items": [
    {
      "trade_date": "2026-07-02",
      "ensemble_score": 0.949,
      "is_anomaly": true,
      "per_detector": { "iforest": 0.967, "statrule": 0.899, "lstm_ae": 0.981 }
    }
    // ...
  ],
  "flagged_dates": ["2026-07-02", "2026-07-03"]
}
```

응답에는 날짜별 탐지기별 점수(per_detector), 앙상블 점수(ensemble_score), 최종 이상 여부(is_anomaly)가 함께 담긴다. 플래그된 두 날짜(2026-07-02·07-03)는 ensemble_score가 0.95를 넘었다.

시장명 정규화도 확인했다. 소문자 `kr`은 `KR`로 정규화되어 정상 처리되고, 아직 지원하지 않는 `JP`는 HTTP 422로 명시적으로 거부된다.

최종적으로 pytest는 159개가 전부 통과했고, 한국 champion 모델 2종(추천·이상탐지)이 생성됐다. 추천 결과는 13행(한국 유니버스 13종 전량), 이상탐지 결과는 3030행이 나왔다. main에 병합하며 Week5를 마무리했다.

## 한계와 배운 점

### 남겨둔 한계

로컬 지표가 비어 있다. 한국 로컬 지수(KOSPI·KOSDAQ)와 로컬 변동성 지표(VKOSPI)는 아직 붙이지 못했다. 그래서 지금은 미국 글로벌 지수(VIX·S&P)를 한국 종목의 리스크 프록시로 그대로 쓴다. 한국 시장 고유의 리스크 신호를 반영하지 못한다는 뜻이고, 다음 과제로 넘겼다. 앞서 승격한 한국 모델의 성능이 게이트를 겨우 넘긴 수준인 것도, 이 프록시의 한계와 무관하지 않다고 본다.

### 이번에 배운 것

가장 크게 남은 배움은 검증을 한 층에 맡기지 않는 것의 실질적 가치다. 설계 단계의 다관점 검토가 꼼꼼해도, 구현이 끝난 코드를 보는 리뷰와 시각이 다른 독립 게이트, 그리고 사람이 직접 응답을 확인하는 마지막 눈이 아니면 잡히지 않는 결함이 분명히 있었다. 이상탐지 F1 오염값이나 소문자 시장명 분리 저장은 층을 나누지 않았다면 서빙까지 흘러갔을 문제다.

게이트 재보정에서 얻은 관점도 실무로 이어진다. 임의로 잡은 숫자를 실데이터로 다시 맞추고, 그 기준에 못 미치는 모델을 자동으로 걸러내는 것. 성능이 안 나오는 모델이 조용히 배포되는 사고를 막는다는 점에서, 이건 모델 성능을 포장하는 일이 아니라 배포 파이프라인의 안전장치를 다루는 일에 가깝다. 실서비스를 전제로 MLOps를 정직하게 운영한다는 게 어떤 것인지 조금 더 감이 잡혔다.

다음 Week에서는 이 로컬 지표 공백을 메우고, 시장별 차등 게이트와 통계적 유의성 검정까지 붙여볼 계획이다.
